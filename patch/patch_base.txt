; The fix (3):
;   TFormMain.FormCreate at 0xAA928 was redirected into a CODE cave so that, before the usual

;
;   TFormMain.FormCreate at 0xAAD52 (the original Close1Click call site near the end of create)
;   was redirected into a cave that:
;   - calls sub_000AB324 (load saved window position / state from INI) while still hidden;
;   - runs the original Close1Click logic, then returns into FormCreate.
;   So the saved geometry is applied _before_ first show, not only later on activate.
;
;   CODE section padding (end of the CODE segment, VirtualSize extended) was filled with those
;   caves (and related helpers). File size stays the same; only unused pad in CODE is used.
;
;   TFormMain.ModusText1Click at 0xAE68B and 0xAE729 (the two SetFocus sites for text/hex grids,
;   offsets +0x310 / +0x314) were redirected to caves that call SetFocus only if FVisible
;   (TControl +0x47) is set, then continue at the original following instructions.
;   Purpose: while the form is still invisible during the early FormCreate/sub_000AB324 work,
;   skip those focus calls (they would be wrong/noisy); once the window is visible, keep the
;   original SetFocus-before-SetSlaveGrid order so single-Tab hex<->text still works.
;
;   TFormMain.FormActivate at 0xAAE3B: the call to sub_000AB324 is replaced with a small stub
;   that only SetFocus'es the hex or text grid according to the current modus flag (0xB5B00),
;   then returns.
;   Purpose: avoid running the full INI/position routine again on activate (position already
;   applied at end of FormCreate); only restore keyboard focus to the right grid.
